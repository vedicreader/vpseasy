Lightsail (boto3)

Lightsail has the same shape as Hetzner (servers, get, server_ip, create, delete) over the boto3 Lightsail client, so vps_deploy works with either. boto3 is an optional extra: pip install 'vpseasy[aws]'. Credentials come from the standard AWS chain (e.g. AWS_PROFILE from SSO). create() is idempotent, attaches a static IP, opens only port 22 (traffic arrives through the Cloudflare tunnel) and enables daily automatic snapshots.

Lightsail runs user data as a shell launch script, not as cloud-config, so create() converts vps_init() YAML with cloud_init_sh(): a POSIX script that applies the same settings (hostname, users with sudo and SSH keys, write_files, apt conf, packages, runcmd), keeps the YAML in /var/lib/vpseasy/cloud-config.yaml, logs to /var/log/vpseasy-init.log and touches /var/lib/vpseasy/ready (or error), which chk_cloud_init() reads. Re-running cloud-init with the YAML in /etc/cloud/cloud.cfg.d was tried on Ubuntu 24.04 and did not create users, so it is not used.

    exclude:NoneType=None, # rsync exclude (blacklist) patterns

    key_pass:NoneType=None, # passphrase for the SSH key, if it's encrypted
    password:NoneType=None, # server password for SSH auth (alternative to key-based auth)
    tout:int=600, # seconds to wait for SSH and cloud-init each before retrying (default 10 minutes)
    retries:int=2, # cloud-init retries before giving up and raising TimeoutError

Provision on any provider (idempotent) → wait for cloud-init → deploy. Returns AttrDict(ip, name, key).

@contextmanager
def patch_to_fakes(calls):
    'Replace wait_ready, deploy, vps_init and subprocess with fakes where vps_deploy resolves them, so no key or known_hosts is touched.'
    g = vps_deploy.__globals__
    ks = 'wait_ready', 'deploy', 'vps_init', 'subprocess'
    o = {k: g[k] for k in ks}
    g['wait_ready'] = lambda *a, **k: calls.append(('wait_ready', a, k))
    g['deploy'] = lambda *a, **k: calls.append(('deploy', a, k))
    g['vps_init'] = lambda name, *a, **k: AttrDict(yaml='#cloud-config\n', key='/tmp/k')
    g['subprocess'] = AttrDict(run=lambda *a, **k: calls.append(('ssh-keygen', a, k)))
    try: yield
    finally: g.update(o)

class FakeProvider:
    def __init__(self, made=()): self.made, self.kw = list(made), None
    def get(self, name): return {'name': name} if name in self.made else None
    def server_ip(self, name): return '192.0.2.9'
    def create(self, name, cloud_init=None, **kw): self.made.append(name); self.kw = kw; return AttrDict(ip='192.0.2.9', name=name, key='/tmp/k')

calls, fp = [], FakeProvider()
with patch_to_fakes(calls): r = vps_deploy('svc', '.', fp, verbose=False, bundle='nano_3_0')

test_eq(fp.kw, dict(bundle='nano_3_0'))

Litestream

litestream_conf() writes a Litestream 0.5 config that streams each SQLite db to an S3-compatible bucket (a Lightsail.bucket(), AWS S3 or Cloudflare R2) under <prefix>/<db path>, so dbs with the same file name never collide. Tested against litestream/litestream:0.5 (v0.5.17); note Litestream ignores unknown config keys silently. litestream_svc() returns a Litestream service’s Compose.svc() kwargs. caddy_stack(..., litestream=dict(dbs=..., bucket=..., endpoint=..., region=...)) wires them in: a one-shot litestream-restore service (restore -if-db-not-exists -if-replica-exists) must complete successfully before app starts, so a fresh server gets its db back before the app can create an empty one; the long-running litestream replicate service starts after app. Credentials come from LITESTREAM_ACCESS_KEY_ID / LITESTREAM_SECRET_ACCESS_KEY in .env. Db paths are container paths and must sit inside one of the app’s vols, otherwise the sidecar would replicate nothing.
